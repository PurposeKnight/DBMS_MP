ABSTRACT

On contemporary university campuses accommodating thousands of students, misplacing valuable belongings—such as student identity cards, scientific calculators, laptops, audio peripherals, keys, and wallets—represents a daily administrative and personal hurdle. The traditional campus recovery ecosystem relies predominantly on fragmented WhatsApp/Telegram broadcast groups or unindexed paper logs maintained independently by scattered security checkpoints.

To resolve these inefficiencies, this project delivers REUNITE, an automated relational database-driven Campus Lost and Found Management System. Formulated according to Boyce-Codd Normal Form (BCNF), the system coordinates 5 core relational entities: USERS, ITEMS, CLAIMS, MATCHES, and NOTIFICATIONS. The solution integrates automated heuristic similarity algorithms that compute correlation percentages between lost and discovered reports, triggers that dispatch alerts, and stored procedures that manage administrative claim approvals. A responsive web client allows students and security personnel to search, report, claim, and evaluate records seamlessly.

1. INTRODUCTION

University campuses operate as dense micro-communities where students and faculty transit between lecture halls, laboratories, dining facilities, and libraries. In the process, valuable personal belongings are frequently misplaced. REUNITE introduces an automated database-first platform for tracking, matching, and returning lost belongings with full accountability.

2. PROBLEM DEFINITION

Existing manual registers and chat groups suffer from a lack of centralized indexing, zero automated matching between lost and found items, and vulnerability to fraudulent claims. REUNITE establishes an auditable, normalized relational architecture with real-time heuristic matching.

3. ER MODEL & RELATIONAL MAPPING

The schema consists of five entities:

  • users (user_id [PK], name, email, role)
  • items (item_id [PK], user_id [FK], item_name, description, category, location, status, item_type)
  • claims (claim_id [PK], user_id [FK], item_id [FK], claim_status)
  • matches (match_id [PK], lost_item_id [FK], found_item_id [FK], similarity_score, match_status)
  • notifications (notification_id [PK], user_id [FK], match_id [FK], message, is_read)

4. DDL & DML STATEMENTS

All tables are defined in database/01_schema.sql and populated via database/02_seed_data.sql.

5. ACADEMIC QUERIES & EVALUATION

Comprehensive implementations of GROUP BY with Aggregate, UPDATE, DELETE, Correlated Subqueries, and Nested Subqueries are provided in database/03_queries.sql and executable via the live web UI.
